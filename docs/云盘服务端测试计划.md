# 云盘服务端测试计划

## 1. 概述

### 1.1 测试目标
确保云盘服务功能的正确性、稳定性、性能和安全性，保证以下核心功能正常运行：
- 文件/文件夹管理（创建、删除、重命名、移动）
- 文件上传/下载
- 分块上传与断点续传
- 文件分享功能
- 存储配置管理
- 配额管理
- 多租户隔离

### 1.2 测试范围

#### 1.2.1 功能测试范围
- 文件夹管理服务
- 文件管理服务
- 分块上传服务
- 文件分享服务
- 存储配置管理服务
- 配额管理服务
- 公司级存储管理器

#### 1.2.2 API测试范围
- `/api/v1/cloud/items/*` - 统一项目管理接口
- `/api/v1/cloud/files/*` - 文件管理接口
- `/api/v1/cloud/folders/*` - 文件夹管理接口
- `/api/v1/cloud/shares/*` - 分享管理接口
- `/api/v1/cloud/files/multipart/*` - 分块上传接口
- `/api/v1/cloud/storage/config/*` - 存储配置管理接口
- `/api/v1/cloud/quota` - 配额管理接口

#### 1.2.3 性能测试范围
- 大文件上传（10GB+）
- 多用户并发上传
- 文件列表查询性能
- 分块上传合并性能

#### 1.2.4 安全测试范围
- 权限控制
- 数据隔离
- 输入验证
- 敏感信息脱敏

### 1.3 测试策略
采用分层测试策略：
1. **单元测试**：覆盖Service层核心业务逻辑
2. **集成测试**：覆盖Repository、Service、Handler三层集成
3. **API测试**：使用HTTP客户端测试完整API接口
4. **E2E测试**：完整流程端到端测试

            wantErr: true,
            errCode: errors.ErrInvalidParam,

        t.Run(tt.name, func(t *testing.T) {
            // Arrange
            db := test.SetupGormTestDB(t)
            setupTestTables(t, db)
            if tt.setup != nil {
                tt.setup(t, db)
            }

            service := NewService(db, mockCompanyStorageManager, mockUserRepo)

            // Act
            folder, err := service.CreateFolder(context.Background(), tt.req, tt.userID)

                assert.Equal(t, tt.errCode, errors.Code(err))
            } else {
                assert.NoError(t, err)
                assert.NotNil(t, folder)

        })
    }

### B. 测试最佳实践

1. **测试独立性**：每个测试应该独立运行，不依赖其他测试
2. **描述性测试名称**：使用 `Test{功能}_{场景}_{预期结果}` 格式
3. **Table-Driven测试**：使用表格驱动测试减少重复代码
4. **使用断言库**：使用 testify/assert 提高可读性
5. **Mock外部依赖**：使用Mock对象隔离被测试代码
6. **测试边界情况**：测试空值、最大值、错误输入等
7. **性能测试**：对关键路径添加基准测试
