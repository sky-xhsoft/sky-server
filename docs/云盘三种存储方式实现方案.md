## 概述

本系统支持三种存储方式：
1. **本地存储** - 文件存储在服务器本地磁盘
2. **阿里云OSS** - 文件存储在阿里云对象存储服务
3. **腾讯云COS** - 文件存储在腾讯云对象存储服务

三种存储方式可以通过配置自由切换，也可以同时配置多种存储类型，通过默认配置来选择使用哪一种。

### 设计目标
- 将云盘功能从主业务系统中独立封装
- 支持独立的用户体系和登录认证
- 保持与现有系统的兼容性
- 支持独立部署和维护
- **支持从数据库读取存储配置，实现多租户独立配置**

系统支持三种认证方式：

```yaml

  - sso:         使用主系统的SSO认证（默认，向后兼容）
```

## 数据库存储配置方案

### 设计目标
1. **多租户支持**：每个公司可以有自己的独立存储配置
2. **灵活切换**：公司级存储配置优先，全局配置作为默认值
3. **向后兼容**：保留配置文件方式作为备选方案

### 数据库表设计

#### 方案一：新建独立表（推荐）

创建专门的 `cloud_storage_config` 表来管理存储配置：

```sql
-- 云盘存储配置表
CREATE TABLE `cloud_storage_config` (
    `ID` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
    `SYS_COMPANY_ID` INT UNSIGNED NOT NULL COMMENT '公司ID',

    -- 存储类型选择
    `STORAGE_TYPE` VARCHAR(20) NOT NULL DEFAULT 'local' COMMENT '存储类型: local, aliyunOSS, tencentCOS',

    -- 本地存储配置
    `LOCAL_BASE_PATH` VARCHAR(500) DEFAULT 'uploads' COMMENT '本地存储基础路径',
    `LOCAL_BASE_URL` VARCHAR(500) DEFAULT '/files' COMMENT '本地存储基础URL',

    -- 阿里云OSS配置
    `ALIYUN_OSS_ENDPOINT` VARCHAR(255) COMMENT '阿里云OSS Endpoint',
    `ALIYUN_OSS_ACCESS_KEY_ID` VARCHAR(255) COMMENT '阿里云OSS AccessKeyID',
    `ALIYUN_OSS_ACCESS_KEY_SECRET` VARCHAR(255) COMMENT '阿里云OSS AccessKeySecret',
    `ALIYUN_OSS_BUCKET_NAME` VARCHAR(255) COMMENT '阿里云OSS Bucket名称',
    `ALIYUN_OSS_CDN_DOMAIN` VARCHAR(500) COMMENT '阿里云OSS CDN域名',

    -- 腾讯云COS配置
    `TENCENT_COS_BUCKET_URL` VARCHAR(500) COMMENT '腾讯云COS Bucket URL',
    `TENCENT_COS_SECRET_ID` VARCHAR(255) COMMENT '腾讯云COS SecretID',
    `TENCENT_COS_SECRET_KEY` VARCHAR(255) COMMENT '腾讯云COS SecretKey',
    `TENCENT_COS_BUCKET_NAME` VARCHAR(255) COMMENT '腾讯云COS Bucket名称',
    `TENCENT_COS_REGION` VARCHAR(50) COMMENT '腾讯云COS 区域',
    `TENCENT_COS_CDN_DOMAIN` VARCHAR(500) COMMENT '腾讯云COS CDN域名',

    -- 通用字段
    `IS_ACTIVE` CHAR(1) NOT NULL DEFAULT 'Y' COMMENT '是否有效(Y/N)',
    `CREATE_BY` VARCHAR(80) COMMENT '创建人',
    `CREATE_TIME` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `UPDATE_BY` VARCHAR(80) COMMENT '更新人',
    `UPDATE_TIME` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

    -- 索引
    UNIQUE KEY `idx_company` (`SYS_COMPANY_ID`),
    INDEX `idx_storage_type` (`STORAGE_TYPE`),
    INDEX `idx_active` (`IS_ACTIVE`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='云盘存储配置表';
```

## 配置说明

### 配置优先级

系统采用以下配置优先级（从高到低）：

1. **数据库公司级配置**：`cloud_storage_config` 表中对应公司的配置（最高优先级）
2. **配置文件配置**：`config.yaml` 中的 `cloud.storage` 配置（备用方案）
3. **系统默认值**：代码中定义的默认值（兜底方案）

### 配置文件结构

```yaml
# 云盘配置（独立于主系统）
cloud:
    # 是否启用云盘功能
    enabled: true

    # 用户认证策略: sso, standalone, both
    authStrategy: "both"

    # 默认存储类型: local, aliyunOSS, tencentCOS
    # 当数据库中没有配置时使用此默认值
    defaultStorage: "local"

    # 存储配置（作为全局默认配置）
    storage:
        # 本地存储配置
        local:
            basePath: "uploads"
            baseURL: "/files"

        # 阿里云OSS配置
        aliyunOSS:
            enabled: false
            endpoint: "oss-cn-hangzhou.aliyuncs.com"
            accessKeyID: "your-access-key-id"
            accessKeySecret: "your-access-key-secret"
            bucketName: "your-bucket-name"
            cdnDomain: ""
            useSSL: true

        # 腾讯云COS配置
        tencentCOS:
            enabled: true
            bucketURL: "https://your-bucket-name.cos.ap-guangzhou.myqcloud.com"
            secretID: "your-secret-id"
            secretKey: "your-secret-key"
            bucketName: "your-bucket-name"
            region: "ap-guangzhou"
            cdnDomain: ""
```

## 快速开始

### 使用本地存储（最简单）

```yaml
cloud:
  enabled: true
  defaultStorage: "local"
  storage:
    local:
      basePath: "./storage"
      baseURL: "/files"
```

无需额外配置，文件将存储在 `./storage` 目录下。

### 使用阿里云OSS

1. **开通OSS服务**
   - 访问 https://www.aliyun.com/product/oss
   - 开通对象存储OSS服务

2. **创建Bucket**
   - 登录阿里云控制台
   - 进入OSS管理控制台
   - 创建新的Bucket
   - 选择合适的地域
   - 权限设置建议：私有读写

3. **获取AccessKey**
   - 访问 https://ram.console.aliyun.com/
   - 创建RAM用户（推荐）或使用主账号AccessKey
   - 授予OSS管理权限

4. **配置应用**
```yaml
cloud:
  defaultStorage: "aliyunOSS"
  storage:
    aliyunOSS:
      enabled: true
      endpoint: "oss-cn-hangzhou.aliyuncs.com"
      accessKeyID: "你的AccessKeyID"
      accessKeySecret: "你的AccessKeySecret"
      bucketName: "你的Bucket名称"
      cdnDomain: ""  # 可选
```

### 使用腾讯云COS

1. **开通COS服务**
   - 访问 https://cloud.tencent.com/product/cos
   - 开通对象存储COS服务

2. **创建Bucket**
   - 登录腾讯云控制台
   - 进入对象存储控制台
   - 创建存储桶
   - 选择合适的地域
   - 权限设置建议：私有读写

3. **获取Secret**
   - 访问 https://console.cloud.tencent.com/cam/capi
   - 新建API密钥或使用现有密钥

4. **配置应用**
```yaml
cloud:
  defaultStorage: "tencentCOS"
  storage:
    tencentCOS:
      enabled: true
      bucketURL: "https://your-bucket.cos.ap-guangzhou.myqcloud.com"
      secretID: "你的SecretID"
      secretKey: "你的SecretKey"
      bucketName: "你的Bucket名称"
      region: "ap-guangzhou"
      cdnDomain: ""  # 可选
```

## API使用方式

### 存储接口方法

```go
type Storage interface {
    // Upload 上传文件
    Upload(ctx context.Context, path string, reader io.Reader, contentType string) (string, error)

    // Download 下载文件
    Download(ctx context.Context, path string) (io.ReadCloser, error)

    // Delete 删除文件
    Delete(ctx context.Context, path string) error

    // Exists 检查文件是否存在
    Exists(ctx context.Context, path string) (bool, error)

    // GetURL 获取文件访问URL
    GetURL(ctx context.Context, path string, expireSeconds int) (string, error)

    // ListObjects 列出对象
    ListObjects(ctx context.Context, prefix string, maxKeys int) ([]Object, error)

    // CopyObject 复制对象
    CopyObject(ctx context.Context, srcPath, dstPath string) error

    // GetObjectInfo 获取对象信息
    GetObjectInfo(ctx context.Context, path string) (*ObjectInfo, error)

    // PresignedUploadURL 获取预签名上传URL（用于前端直传）
    PresignedUploadURL(ctx context.Context, path string, expireSeconds int, contentType string) (string, error)

    // InitiateMultipartUpload 初始化分块上传
    InitiateMultipartUpload(ctx context.Context, path string) (string, error)

    // PresignedChunkUploadURL 获取分块预签名上传URL
    PresignedChunkUploadURL(ctx context.Context, path string, uploadID string, chunkNumber int, expireSeconds int, contentType string) (string, error)

    // CompleteMultipartUpload 完成分块上传
    CompleteMultipartUpload(ctx context.Context, path string, uploadID string, partETags []string) (string, error)
}
```

### 使用示例

```go
// 示例1: 上传文件
file, err := os.Open("local-file.pdf")
if err != nil {
    return err
}
defer file.Close()

url, err := storage.Upload(ctx, "cloud/user-123/document.pdf", file, "application/pdf")
if err != nil {
    return err
}
fmt.Println("文件已上传:", url)

// 示例2: 下载文件
reader, err := storage.Download(ctx, "cloud/user-123/document.pdf")
if err != nil {
    return err
}
defer reader.Close()

// 示例3: 获取访问URL
// 公开文件永久URL
publicUrl, err := storage.GetURL(ctx, "cloud/user-123/document.pdf", 0)

// 私有文件临时URL（7200秒后过期）
signedUrl, err := storage.GetURL(ctx, "cloud/user-123/document.pdf", 7200)

// 示例4: 删除文件
err = storage.Delete(ctx, "cloud/user-123/document.pdf")

// 示例5: 检查文件是否存在
exists, err := storage.Exists(ctx, "cloud/user-123/document.pdf")
```

## 大文件分块上传

### 分块上传流程

```
┌─────────────────────────────────────────────────────────┐
│                     前端                              │
└────────────────────────┬────────────────────────────────┘
                         │
                         │ 1. 请求初始化分块上传
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│  POST /api/v1/cloud/multipart/init                   │
│  { path: "cloud/user-123/large-file.zip" }          │
└────────────────────────┬────────────────────────────────┘
                         │
                         │ 2. 返回 uploadId
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│       循环上传每个分块（并发进行）               │
└────────────────────────┬────────────────────────────────┘
                         │
                         │ 3. 请求获取分块预签名URL
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│  POST /api/v1/cloud/multipart/chunk-url             │
│  { uploadId, chunkNumber }                          │
└────────────────────────┬────────────────────────────────┘
                         │
                         │ 4. 返回预签名URL
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│     前端直接上传分块到云存储（不经过服务端）   │
└────────────────────────┬────────────────────────────────┘
                         │
                         │ 5. 重复步骤3-4，直到所有分块上传完成
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│  POST /api/v1/cloud/multipart/complete              │
│  { uploadId, partETags: [...] }                     │
└────────────────────────┬────────────────────────────────┘
                         │
                         │ 6. 服务端通知云存储合并文件
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│               返回最终文件信息                       │
└─────────────────────────────────────────────────────────┘
```

### 分块大小建议

| 文件大小 | 推荐分块大小 | 分块数量 |
|----------|-------------|---------|
| < 100MB | 不分块（直接上传） | 1 |
| 100MB - 1GB | 50MB | 2-20 |
| 1GB - 10GB | 100MB | 10-100 |
| > 10GB | 200MB | 50+ |

## 性能优化建议

### 本地存储优化

- 使用高性能SSD存储
- 合理设置文件目录结构，避免单目录文件过多
- 可以配置Nginx/Apache直接提供静态文件服务

### 云存储优化

- 选择离服务器近的区域，减少延迟
- 使用CDN加速静态资源访问
- 合理设置分块大小（推荐50MB-100MB）
- 开启云存储的服务端加密
- 配置合理的生命周期规则清理旧文件

---

## 安全建议

1. **使用RAM子账号** - 不要使用主账号AccessKey
2. **最小权限原则** - 只授予必要的权限
3. **定期轮换密钥** - 定期更换AccessKey/Secret
4. **开启服务端加密** - 敏感数据加密存储
5. **配置访问控制** - 限制来源IP
6. **使用HTTPS** - 传输过程加密
