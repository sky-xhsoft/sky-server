## Phase 3 - 通用 CRUD 服务实现 ✅

**完成时间**: Phase 2 之后
**状态**: 完成

### 主要成果

- 实现通用 CRUD 服务层
  - `Create` - 新建记录
  - `Update` - 更新记录
  - `Delete` - 删除记录
  - `GetByID` - 获取单条
  - `Query` - 查询列表
  - `Count` - 统计总数
- 实现字段赋值策略
  - `pk` - 主键自动生成
  - `docno` - 单据编号生成
  - `createBy` / `operator` - 操作用户
  - `sysdate` - 系统时间
  - `byPage` - 页面输入
  - `select` - 下拉选择
  - `fk` - 外键关联
  - `ignore` - 忽略
- 实现审计字段自动填充
  - `CREATE_BY`, `CREATE_TIME`
  - `UPDATE_BY`, `UPDATE_TIME`
  - `SYS_COMPANY_ID`
- 软删除支持 (`IS_ACTIVE`)
- 分页查询支持

### 核心设计

- **反射驱动**: 通过反射动态赋值，无需硬编码
- **元数据驱动**: 所有行为由元数据决定
- **可复用**: 任何表都自动获得 CRUD 能力

## Phase 5 - 审核流程（工作流） ✅

**完成时间**: Phase 4 之后
**状态**: 完成

### 主要成果

- 实现完整的单据生命周期管理
  - **新增** → 待审核
  - **提交** → 已提交
  - **审核** → 已审核
  - **反提交** → 退回修改
  - **作废** → 已作废
- 状态流转控制
  - 验证状态转换合法性
  - 权限检查（谁能审核）
- 审核日志记录
  - 记录审核人、审核时间、审核意见
- 状态权限控制
  - 已审核单据不能修改
  - 只有待审核才能提交

### 状态机

```
  新增
   ↓ 提交
  待审核
   ↓ 审核
  已审核 ← 反提交 ←
   ↓
  作废
```

### 代码规模
- 约 400 行代码

## Phase 8 - 权限管理（新 RBAC） ✅

**完成时间**: Phase 7 之后
**状态**: 完成

### 主要成果

- 重新设计 RBAC 权限模型
  - `sys_user` - 用户
  - `sys_company` - 公司（租户）
  - `sys_groups` - 权限组
  - `sys_directory` - 安全目录
  - `sys_group_prem` - 权限分配
- 实现权限检查核心
  - 支持多级权限控制
  - 支持访问级别 (SGRADE)
- 支持多租户隔离
  - 按 `SYS_COMPANY_ID` 自动过滤

### 权限模型

- **用户** → 属于多个**权限组**
- **权限组** → 有多个**目录权限**
- **目录** → 映射到**表**
- **权限值** → 1=读, 3=读写, 5=读+提交 等

### 代码规模
- 约 500 行代码

## Phase 13 - 云盘功能设计与实现 ✅

**完成时间**: Phase 12 之后
**状态**: 完成

### 主要成果

  - 基于Go标准库文件系统

  - `cloud_folder` - 文件夹（树形结构）

  - 文件夹管理（创建、删除、重命名、树形构建）

  - 文件分享（公开、密码保护、私密分享、过期控制）
  - 配额管理（空间检查、单文件大小限制、使用量统计）

### 技术亮点

- 树形文件夹结构递归构建
- 统一存储路径设计 `cloud/{userID}/{YYYY/MM/DD}/{uuid}.ext`
- 三级智能配额控制
